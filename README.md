# 望潮 · 币安交易员监控

个人使用的公开成交观察台：后台采集币安带单员成交，保存历史与修订版本，重建仓位，通过钉钉或飞书推送手机提醒。默认观察 **熬鹰资本**（5075281354358777856）。

**不需要币安 API Key，不执行交易。** 当前数据源是币安网页使用的未公开承诺稳定性的 friendly 接口，公开记录可能延迟、缺失或变更；不能承诺逐笔实时。连接异常会明确显示，失败批次不会被当成空仓。

## 本地启动

需要 Node.js 22.13+（推荐 24）和 pnpm 10。

```sh
git clone https://github.com/Wenguanming/Trading-System.git
cd Trading-System
cp .env.example .env
pnpm install
pnpm dev
```

打开 http://127.0.0.1:5173 。后端位于 http://127.0.0.1:8787 。

首次启动自动补查最近 7 天，完整成功后开始每 15 秒增量查询。第一次导入的历史成交不会推送通知。网络失败时最多退避到 5 分钟。

默认使用本地嵌入式 PostgreSQL（PGlite），数据写入 `data/live`，无需本地安装数据库。一个数据目录/数据库只运行一个采集实例。更换交易员或运行模式时使用独立数据目录；身份校验会阻止混入另一位交易员的数据。

演示模式：

```sh
pnpm demo
```

先停止同端口的开发服务。演示数据与真实数据分库存储，界面显示演示标识，外部通知强制关闭。若已配置远程 DATABASE_URL，请清空该配置或为演示分配独立数据库。

## 手机通知

在钉钉群添加「自定义机器人」，安全设置选择「加签」；将 Webhook 和 SEC 开头的密钥写入服务端 `.env`：

```dotenv
NOTIFY_PROVIDER=dingtalk
NOTIFY_WEBHOOK=你的机器人Webhook
NOTIFY_SECRET=你的SEC加签密钥
```

飞书群自定义机器人配置同理，使用 `NOTIFY_PROVIDER=feishu`。启用签名校验并填写对应密钥。

保存后重启服务，在「提醒与设置」点击「发送测试通知」。手机须允许钉钉/飞书通知。密钥不会返回给浏览器。未配置通道时，新增成交仍然保存，但不会在之后配置时突然推送全部旧消息。

消息包括品种、方向、累计成交量、均价、成交/检测时间、推算剩余仓位、记录标识。延迟超过两分钟的成交标为延迟发现。通知队列持久化，失败指数退避，最多 8 次，之后可手动重试；超过 24 小时的积压停止自动发送。

**通知是至少一次发送尝试。** 若机器人已收到消息但网络响应丢失，重试可能产生重复通知，不能承诺外部通道严格只送一次。每条消息附记录标识便于识别。

## 仓位校准

公开成交可直接监控；仓位根据可用数据自动选择来源：

- 币安允许公开当前持仓时，直接读取官方网页仓位。每约 60 秒尝试一次，和成交请求共用至少 6 秒的串行请求间隔。
- 未公开（`positionShow=false`）或可见性未知时，不把空数组当成空仓。需要用户确认起点，之后按成交重建。
- 「仅所填仓位」适用于单个仓位截图，只跟踪填写的合约和方向，其余仓位保持未知。
- 「整个账户」须填写该时点全部仓位；留空明确表示当时整个账户空仓。旧版校准保持此语义。

在「提醒与设置」选择已采集范围内的基准时刻，填写数量、均价，可选填写杠杆和全仓/逐仓。勾选相应范围的确认后保存。截图需要完整日期和时间，不能使用今天的价格或当前时间替代历史观测。基准时间按浏览器本机时区输入，展示与筛选采用北京时间。

减仓量超过持仓时停止推算，要求重新校准。手动杠杆和模式不是自动核实的实时字段，需自行更新；全部平仓后清除，重开仓不沿用。ROI = 浮盈 ÷（当前仓位价值 ÷ 杠杆）×100%，标为估算。未包含所有费用。

推算浮盈使用对应币安 U 本位合约标记价格，每 5 秒尝试更新；超过 60 秒失效。公开仓位使用该次接口返回的标记价格。强平价仅在仓位接口明确返回时展示，不用固定维持保证金率猜测。带单保证金余额来自项目详情，不代表交易员的所有账户资产，也不保证上游逐秒刷新。

## 仓位记录

- 仓位数量、成本、杠杆、范围或成交版本改变时立即留档；正常情况下每分钟保存一次价格/浮盈快照。
- 记录包括观察时间、成交同步水位、来源、范围、可靠性、数量、开仓均价、标记价及时间、仓位价值、浮盈、杠杆、模式、ROI、上游强平价、保证金余额及其采集时间。
- 历史快照不可变；重新校准会生成新快照，保留旧的基准和成交版本摘要。原成交修订仍保存在 `trade_versions`。
- 同一来源与基准下确认平仓时，记录数量为 0；接口失败、隐藏或切换校准范围不会被伪造为平仓。
- 首次启用只能开始记录当时的观察结果，不会用当前价格回填过去。一次批量发现多笔成交时保存该次采集后的状态，不能视为逐笔成交瞬间的仓位。
- 在「仓位记录」按合约和日期筛选、展开明细、导出 CSV。单次最多导出 10000 条快照，超过时缩小日期范围。
- 表 `position_snapshots` 自动迁移创建，不清除现有成交与通知数据。历史没有自动删除策略，请定期备份并关注磁盘增长。
- 查询 `GET /api/positions/history` 和导出 `GET /api/positions/export` 与现有接口使用相同登录保护。

2026-11-18 实测：熬鹰资本项目公开详情返回 `positionShow=false`，匿名仓位接口为空数组；项目保证金余额仍可读取。当前需校准后才能自动记录具体仓位。没有将示例截图直接保存为该交易员的实时仓位。

## 数据准确性与边界

- 当前仓位：GET https://www.binance.com/bapi/futures/v1/friendly/future/copy-trade/lead-data/positions?portfolioId=...
- 项目详情：GET https://www.binance.com/bapi/futures/v1/friendly/future/copy-trade/lead-portfolio/detail?portfolioId=...
- 成交数据源：POST https://www.binance.com/bapi/futures/v1/friendly/future/copy-trade/lead-portfolio/order-history
- 分页：最多七天一个窗口，请求间隔至少六秒，pageSize=50，按 indexValue 和 total 读取；部分失败不推进采集水位。
- 增量：从上次成功查询的结束时间向前重叠 10 分钟，持续补查；网络中断时从上次水位追赶。
- 长时间停机：超过 30 天停止推进水位并提示重新建库和校准，避免默默跳过历史。
- 当前接口没有稳定订单 ID。使用交易员、合约、方向、买卖侧、下单毫秒作为复合标识；累计数量/均价更新保留版本，不作为新增仓位重复累加。同批次同标识不同内容拒绝导入。
- 无法绝对区分跨次查询中同一毫秒独立订单和累计成交修订，这是上游数据限制。
- 如果公开记录迟到超过 10 分钟重叠窗口，可能漏掉。第一版不承诺所有历史修订都能被检测。
- 当日已实现盈亏为当日公开成交的 totalPnl 之和，不等同于账户当日净收益，未合并全部手续费与资金费。
- 数据采集、行情刷新、页面连接状态分别显示；“采集成功”不等同于币安数据无延迟。
- 仓位数值使用 decimal.js 十进制计算；原始响应保存在交易记录及历史版本中。
- 不自动猜测登录态、绕过 WAF 或访问限制；相关错误会在看板显示。

## 生产构建

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm start
```

生产构建将前后端统一运行在 8787 端口。本地监听默认仅允许回环地址。监听非本机地址必须配置至少 12 位 APP_PASSWORD，所有数据接口和 SSE 都受登录保护。通过 HTTPS 访问时设置 COOKIE_SECURE=true。

## Docker / PostgreSQL 部署

在 `.env` 设置：

```dotenv
APP_PASSWORD=请替换为至少12位的访问密码
POSTGRES_PASSWORD=请替换为随机数据库密码
COOKIE_SECURE=true
```

数据库密码建议用 URL 安全字符（例如随机十六进制字符串）；若包含特殊字符，自行构造并编码 DATABASE_URL。

```sh
docker compose up -d --build
```

Compose 启动 PostgreSQL 和看板。看板端口只绑定服务器 127.0.0.1:8787，数据库不暴露宿主机端口。在前面配置 Caddy/Nginx HTTPS 反向代理后，用手机访问域名，再添加到主屏幕。

Caddy 示例（替换域名）：

```caddy
watch.example.com {
  reverse_proxy 127.0.0.1:8787
}
```

Nginx 代理 SSE 时关闭 proxy_buffering，并将 proxy_read_timeout 设置为至少 60s。服务使用 HTTP-only、SameSite=Strict 的签名登录 Cookie；登录接口限流。请使用 HTTPS，并定期备份数据库。

PWA 仅提供桌面入口与离线提示。**手机锁屏提醒由钉钉/飞书承担，不依赖网页常驻；本版未实现原生 APK 和 Web Push。** 本机电脑休眠后采集会停止，长期运行应部署到服务器。

## 项目结构

- `src/`：React 响应式看板、记录筛选、设置与校准。
- `shared/`：前后端数据协议。
- `server/source.ts`：币安采集与独立演示源。
- `server/domain.ts`：成交归一化、重复检测、仓位计算。
- `server/repository.ts`：原子入库、版本与通知 outbox。
- `server/service.ts`：调度、补查、退避与状态。
- `server/notifications.ts`：钉钉 / 飞书签名发送、持久化重试。
- `server/http.ts`：鉴权、SSE、查询、导出、操作接口。
- `tests/`：数学一致性、重复/修订、回滚、分页、通知与鉴权测试。

数据库连接可通过 DATABASE_URL 切换为标准 PostgreSQL，SQL 与 PGlite 共用。服务器和数据路径由 `.env.example` 中的环境变量配置。
